# CSRF-Schutz und Session-Härtung Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Alle POST-Requests des CRM mit einem Session-Token gegen CSRF schützen und das Session-Cookie härten.

**Architecture:** Zwei globale Slim-Middlewares (`SessionMiddleware` startet die Session mit sicheren Cookie-Parametern, `CsrfMiddleware` prüft das Token) plus ein `CsrfTokenManager`, der das Token in `$_SESSION` hält und über Twig-Funktionen in die Formulare kommt.

**Tech Stack:** PHP 8.2, Slim 4, PHP-DI, Twig 3, PHPUnit 10, slim/psr7.

**Spec:** `docs/superpowers/specs/2026-10-13-csrf-design.md`

## Global Constraints

- Branch: `feat/csrf` (existiert, enthält die Spec). Commits nach Conventional Commits, deutsch, **ohne** Hinweis auf KI/Claude und ohne `Co-Authored-By`-Trailer.
- `declare(strict_types=1)` in jeder neuen PHP-Datei, PSR-12.
- Keine neuen Composer-Abhängigkeiten.
- Formularfeld heisst `_csrf`, Header `X-CSRF-Token`, Session-Schlüssel `_csrf_token`, Token = `bin2hex(random_bytes(32))` (64 Hex-Zeichen), Vergleich mit `hash_equals`.
- Session-Cookie: Name `$_ENV['SESSION_NAME']` (Fallback `mediahuus_crm_session`), `httponly`, `samesite=Lax`, `path=/`, `secure` nur bei HTTPS; `session.use_strict_mode=1`.
- Texte: 403 «Die Sitzung ist abgelaufen oder das Formular ist veraltet. Bitte Seite neu laden und erneut versuchen.»; 413 «Die hochgeladenen Dateien sind zu gross.»; JSON-Fehler `{"success":false,"error":"csrf"}`.
- Buttons/Links im Fehler-Template mit dem im Projekt üblichen Emerald-Grün (`mediahuus-button-primary`).
- Tests laufen mit `ddev exec vendor/bin/phpunit`.

## Review Focus

- **Zwei Tabs offen, in einem wird gespeichert** → das andere Formular muss weiterhin funktionieren (Token bleibt pro Session gleich). Test: `CsrfTokenManagerTest::testTokenStableAcrossCalls`.
- **Login-Formular lange offen, Session abgelaufen** → 403-Seite mit Link zurück zu `/login`, kein Whitescreen. Test: `CsrfMiddlewareTest::testMissingTokenRendersHtml403WithBackLink`.
- **Ankauf mit grossen Ausweisfotos über `post_max_size`** → 413 statt 403. Test: `CsrfMiddlewareTest::testOversizedBodyReturns413`.
- **«Cache leeren» per fetch** → JSON-Antwort, nicht HTML. Test: `CsrfMiddlewareTest::testHeaderRequestGetsJsonError`.
- **Token als Array statt String im Body** (`_csrf[]=x`) → ungültig, keine PHP-Warnung. Test: `CsrfTokenManagerTest::testNonStringIsInvalid`.

**Interfaces:**

Liest/schreibt direkt `$_SESSION['_csrf_token']` (Tests setzen `$_SESSION = []` in `setUp`; das weicht bewusst von der Spec-Formulierung «injizierbares Backend» ab – einfacher, gleich testbar).

- [ ] **Step 1: Failing tests schreiben**

```php
protected function setUp(): void { $_SESSION = []; $this->m = new CsrfTokenManager(); }

public function testGeneratesHexToken(): void
{ $this->assertMatchesRegularExpression('/^[0-9a-f]{64}$/', $this->m->getToken()); }

public function testTokenStableAcrossCalls(): void
{ $this->assertSame($this->m->getToken(), (new CsrfTokenManager())->getToken()); }

public function testValidToken(): void
{ $this->assertTrue($this->m->isValid($this->m->getToken())); }

public function testWrongOrEmptyTokenInvalid(): void
{
    $this->m->getToken();
    $this->assertFalse($this->m->isValid(str_repeat('a', 64)));
    $this->assertFalse($this->m->isValid(''));
    $this->assertFalse($this->m->isValid(null));
}

public function testNonStringIsInvalid(): void
{ $this->m->getToken(); $this->assertFalse($this->m->isValid(['x'])); }

public function testInvalidWhenNoTokenInSession(): void
{ $this->assertFalse($this->m->isValid('abc')); $this->assertArrayNotHasKey('_csrf_token', $_SESSION); }

public function testRegenerateChangesToken(): void
{ $old = $this->m->getToken(); $this->m->regenerate(); $this->assertNotSame($old, $this->m->getToken()); }
```

```php
testPostWithValidBodyTokenPasses()       // withParsedBody(['_csrf' => $token]) → 200
testPostWithValidHeaderTokenPasses()     // withHeader('X-CSRF-Token', $token) → 200
testMissingTokenRendersHtml403WithBackLink()
    // POST /login ohne Token, Referer 'http://crm.test/login', Host crm.test
    // → 403, Body enthält 'Die Sitzung ist abgelaufen' und '/login'; Handler NICHT aufgerufen
testForeignRefererFallsBackToRoot()      // Referer 'https://evil.example/x' → back_url '/'
testWrongTokenReturns403()

                                         // Body == '{"success":false,"error":"csrf"}'
testOversizedBodyReturns413()            // $postMaxBytes = 100, Content-Length 500, leerer Body
                                         // → 413, Body enthält 'zu gross'
testLogsWarningOnRejection()             // Logger-Mock expects(once())->method('warning')
```

- [ ] **Step 2:** `ddev exec vendor/bin/phpunit tests/Middleware/CsrfMiddlewareTest.php` → FAIL.
- [ ] **Step 3:** Middleware implementieren. Reihenfolge der Prüfung: Methode sicher → durch; Token gültig → durch; Body leer **und** `Content-Length` > `$postMaxBytes` → 413; sonst 403. JSON statt HTML, wenn `Accept` `application/json` enthält oder `X-CSRF-Token` gesetzt ist. `back_url`: Pfad des Referers, wenn dessen Host gleich `$request->getUri()->getHost()`, sonst `/`.
